# SEO audit and fixes — 29 October 2026

Audit of the website codebase using the checklists of [claude-seo](https://github.com/AgriciDaniel/claude-seo) (technical, schema, content/E-E-A-T, AI search, hreflang, sitemap). The live site could not be fetched from the audit environment, so findings come from the code and a local production build (`pnpm build` + `pnpm start`). Core Web Vitals and Search Console data were **not** measured.

## Fixed in this change

| Priority | Finding | Fix |
| --- | --- | --- |
| Critical | `/ar` homepage and `/ar/tools/schengen-calculator` declared the English URL as canonical, so the Arabic pages could not be indexed. | Each language now self-canonicalises (`localeAlternates()` in `lib/seo.ts`). |
| High | No hreflang anywhere except four legal pages; Google could not pair English and Arabic pages. | `withArabicMeta()` (`lib/page-meta.ts`) adds `en` / `ar` / `x-default` to every indexable page that uses it; home, pricing, how-it-works, app, calculator and destination pages set them directly. Noindex pages get none. |
| High | Sitemap listed 2 Arabic URLs out of ~87 and stamped every static page "modified today" on each build. | `app/sitemap.ts` lists both languages for every indexable page with hreflang links (174 URLs, all return 200 locally). Static pages no longer claim a fake `lastmod`; posts keep their publish date. |
| High | 29 destination landing pages (×2 languages) had no structured data. | `Service` (with the 249 AED `Offer`) and `BreadcrumbList` JSON-LD per destination, localised. |
| High | Share image was the 873×216 transparent logo declared as 1200×630. Pages that set their own Open Graph block (pricing, how-it-works, calculator, legal pages…) had no `og:image` at all, and X/Twitter cards showed the homepage title on every page. | New 1200×630 cards `public/og/ezvisa-og.png` and `ezvisa-og-ar.png` (regenerate with `node scripts/generate-og-images.mjs`). Every page now has a complete Open Graph block; the root Twitter block only sets the card type, so title and image follow each page. |
| Medium | `Organization.sameAs` pointed at `facebook.com/ezvisa`, `twitter.com/ezvisa`, `youtube.com/@ezvisa` — not the profiles linked in the footer. | `SOCIAL_PROFILES` in `lib/seo.ts` matches the footer (YouTube `@ezvisa_dxb`, Instagram `ezvisa.net`, Facebook `ezvisadxb`, TikTok `@ezvisa.net`). Removed `twitter:creator @ezvisa` (no X account is linked). |
| Medium | Organization logo declared 600×200 (real 873×216); no founder. | Correct size; `founder: Kirolos Edward` added (E-E-A-T). |
| Medium | Blog `Article` schema credited "EZvisa Team" as a Person, used the English headline on Arabic pages and a relative image URL. | Author is the Organization, headline/`inLanguage` follow the page language, absolute image, `BreadcrumbList` added. A post without an Arabic body canonicalises its `/ar` URL to English and gets no hreflang (`translated: false`). |
| Low | About and Contact titles rendered "… EZvisa … \| EZvisa". `generator: v0.app` meta. OG locale `ar` instead of `ar_AE`. | Fixed. |
| Low | No `llms.txt` for AI assistants. | `public/llms.txt` summarises the service, price, exclusions and key pages. |

## Recommended next steps (not done here)

1. **Google Search Console and Bing Webmaster Tools** — verify the domain with a DNS TXT record (the placeholder verification meta tags were removed earlier), submit `https://www.ezvisa.net/sitemap.xml`, then watch *Pages → Indexed* for the `/ar` URLs and *International targeting* for hreflang errors over the next 2–4 weeks.
2. ~~**Email consistency**~~ — done: the owner confirmed `hello@ezvisa.net`; Contact and Terms no longer use `info@ezvisa.net`.
3. **Company details** — `COMPANY_DETAILS_READY` is `false`. Once the legal name, licence and address are confirmed, add `legalName` and `address` to the Organization schema.
4. **Content depth (E-E-A-T)** — guides are ~1-minute reads. Expand the top commercial topics (e.g. "France visa from Dubai", "Schengen visa requirements for UAE residents", "Schengen appointment Dubai") with reviewed-by bylines and "last updated" dates; link each guide to its destination and checklist pages.
5. **Reviews and Google Business Profile** — no ratings are published (correctly). Collecting genuine Google reviews is the largest remaining trust/local signal; never add rating schema without real reviews.
6. **Performance** — run PageSpeed Insights / CrUX for `/`, `/ar`, a destination and a guide (INP, LCP, CLS); the homepage loads several Globi videos.
7. **Markup** — the root layout wraps pages in `<main>` and the homepage adds another `<main>`; use a single main landmark.
8. FAQPage schema on home and app is kept: Google retired FAQ rich results in May 2026, so it brings no SERP feature but is harmless.

## Using claude-seo in this repo

`.claude/settings.json` registers the `agricidaniel-claude-seo` marketplace and enables `claude-seo`. Claude Code asks each contributor to trust and install it the first time. Then run `/seo setup` once, and for example `/seo audit https://www.ezvisa.net`, `/seo hreflang https://www.ezvisa.net`, `/seo geo https://www.ezvisa.net` or `/seo content-brief "schengen visa from dubai"`. Full audits need network access to the live site.
