EZvisa File Preparation Flow

When a paid case reaches Preparation, an AI agent drafts the visa file. A specialist checks every draft in the staff console before anything is used.

Live exists today To build planned, not working yet Needs a person a specialist decides Dashed boxes are planned steps.

1The whole journey

For developers: triggers in app/admin/cases/[id]/actions.ts (reviewDocument, changeStage) and app/admin/files/actions.ts (sendToAutomation) call notifyAutomation() in lib/automation/make.ts. Make reads GET /api/automation/cases/:id and writes PUT …/parts into the file_parts table (states todo, draft, done). The board is components/staff/file-prep.tsx; Ready is set by assembleAndReady(). Planned: lib/automation/start.ts, automation_runs table, Claude API agent.

2One switch, three modes

For developers: planned console setting automation.mode (off, make, in_app) read by lib/automation/start.ts; environment override FILE_PREP_AGENT=off. Shared write in lib/automation/save-parts.ts (moved from the PUT /parts route). Make needs MAKE_API_SECRET and MAKE_WEBHOOK_URL; In app needs ANTHROPIC_API_KEY.

3Inside one run

For developers: @anthropic-ai/sdk Tool Runner, model claude-opus-5-5, effort high, strict Zod tools: search_flights, search_hotels, drive_prepare_case_folder, drive_save_file, submit_file_preparation. Tools without keys return { configured: false }; status becomes to_book_by_staff.

4Run status

For developers: table automation_runs (planned migration 014_file_prep_agent.sql): status queued, running, succeeded, needs_info, failed; heartbeat_at for stale detection; a partial unique index allows one queued or running row per case; reason includes rerun.

For developers: parts on the board are form, cover_letter, flight, hotel, itinerary, checklist (PART_KEYS); the data check travels as the note and missing_info. Drive subfolders: 01 Application form, 02 Cover letter, 03 Flight reservation, 04 Hotel reservations, 05 Itinerary, 06 Client documents, 07 Checklist.

6Rules the agent never breaks

  • Never submits anything to an embassy, visa centre, airline or hotel.
  • Never pays for anything or books a paid fare.
  • Never contacts the customer.
  • Never invents information. Anything missing is written "TO CONFIRM".
  • Never overwrites a part a person marked Done.
  • The demo staff session never calls the AI, Drive or search.

For developers: "never over done" is already enforced for Make in app/api/automation/cases/[id]/parts/route.ts (already_done_by_staff); the demo rule exists in sendToAutomation and extends to every tool.

7Where you control it in the staff console

For developers: boards live under app/admin/: files, cases/[id], settings, notifications, audit, overview, guide, served at /staff/…. Starting a run needs the files permission; the setting is admin only. Guide text in lib/staff/guide.ts.

The owner's checklist, from Part A of the build instructions.

  • Anthropic API key, with a monthly spend limit
  • Google Shared Drive with a service accountoptional
  • A flight and hotel search keyoptional
  • A test case (invented person, test-mode payment, approved test documents)

9Cost

$0.40 to $1.50per case, with Claude Opus 5.5 ($4 per million input tokens, $20 per million output tokens), before any flight or hotel search fees. Estimate, to be confirmed by the first test runs.

For developers: cost is computed from usage (input, output, cache read, cache write) in one tested function and saved as cost_usd on the run; the monthly budget setting stops new runs when reached.

10Suggestions before the build

Review notes from drawing the flow, 1 November 2026. These are proposals for the owner, not part of the planned flow until he adopts them.

  1. Start by button first, automatic start later. The last approval starts a paid run even if a document was approved by mistake and reversed a minute later. Keep "start automatically" off for the first month; staff press Draft with automation when the case is ready.
  2. Protect edited drafts, not only Done. Run again replaces every draft that is not Done, including one a specialist has already edited. Either count an edited draft as protected, or show "2 edited drafts will be replaced" before the rerun starts.
  3. Make Run again cheaper. After Needs info, a rerun should reuse the Drive folder and the protected parts and redraft only what the new information changes, instead of a full-price second run.
  4. Unverified country means Needs info. A destination whose checklist is not yet verified from its official page should never end as Succeeded; force Needs info so no unchecked checklist leaves the agent as a quiet warning.
  5. Decide document reading before the session. Whether the agent reads uploaded documents or only the typed answers changes the privacy policy, the cost estimate and the data check. Settle it in Part A, not mid-build.
  6. Per-run dollar cap. The monthly budget stops new runs, but one runaway case can spend most of it. Add a cap per run (for example $3) next to the step cap.
  7. Set expectations on flights and hotels. No search provider gives a visa-grade reservation, so the agent's output is an options list and staff place the holds. Say so in the agent's note so the team does not wait for a PDF.
  8. Leave room for the letter's language. Cover letters stay in English for now, but keep a field for the embassy's language, since some consulates prefer it.

For developers: items 1, 2 and 4 touch lib/automation/start.ts, lib/automation/save-parts.ts and lib/automation/checklists.ts in the build prompt; item 6 is one more cap beside the step and token caps; the rest are settings or copy.
